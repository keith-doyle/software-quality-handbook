# Retrospective

## What went well

We were able to complete all three sections of the handbook and follow a Git workflow using branches and pull requests. The use of pull requests helped us review each other’s work and improve the quality of the content.

## What did not go well

There were some issues with Git, such as working on the wrong branches and mixing changes across different files. This caused confusion and required time to fix. Communication could also have been clearer at times.

## What we would do differently

If we were doing this again, we would:
- plan branch usage more clearly from the start
- avoid mixing multiple tasks in the same branch
- communicate more before making changes
- review pull requests more consistently

## Key takeaway

This project showed that using Git properly is important for teamwork. Small mistakes in workflow can cause problems, but fixing them helped us understand how to work better as a team.
