# Retrospective

## What went well

We successfully completed all three sections of the handbook: Task Estimation, Code Reviews, and Unit Testing. Using Git branches and pull requests allowed us to work on different parts of the project while still reviewing each other’s work. Feedback through pull requests helped improve clarity and ensured the content was more practical and consistent.

## What did not go well

There were some issues with Git usage during the project. At times, work was completed on the wrong branches or mixed across different files, which caused confusion and required cleanup. For example, comments intended for one section were accidentally placed in another file, which led to additional fixes.

Communication could also have been clearer at certain points, particularly when deciding who was working on specific parts of the project.

## What we would do differently

If we were doing this project again, we would:
- plan branch usage more clearly from the beginning
- avoid mixing multiple tasks in the same branch
- communicate more clearly before starting new work
- review pull requests more consistently before merging
- define responsibilities more strictly to avoid confusion

## Key takeaway

This project highlighted the importance of structured teamwork and proper version control. While mistakes were made, resolving them helped us better understand how to use Git effectively in a collaborative environment.
