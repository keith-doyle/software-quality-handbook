# Software Quality Handbook – Project Plan

 1. Overview

This project is about creating a Software Quality Handbook for a small startup team. Right now, different engineers are working in different ways, which is causing inconsistent results and bugs making it into production.

The aim of this handbook is to set out clear and practical guidelines so everyone on the team follows a more consistent approach.

---

 2. Topics

The handbook will cover three main areas:

- Task Estimation in Scrum  
- Code Reviews  
- Unit Testing and Test Coverage  

Each section will include:
- a short explanation of the topic  
- good practices to follow  
- bad practices to avoid  
- real-world issues or examples  
- links to useful resources  

---

 3. Project Phases

The work will be done in stages:

**Phase 1 – Setup**
- Create the GitHub repository  
- Set up the file structure  
- Agree on workflow  

**Phase 2 – Research**
- Find 5 sources for each topic  
- Focus on practical and real-world content  

**Phase 3 – Outlining**
- Plan the structure of each section before writing  

**Phase 4 – Writing**
- Write the main content  
- Improve it using feedback from pull requests  

**Phase 5 – Formatting**
- Add diagrams and improve layout  
- Make sure it’s easy to read  

**Phase 6 – Contributions**
- Record who did what  

**Phase 7 – Retrospective**
- Reflect on how the project went  

**Phase 8 – Final Check**
- Review everything before submission

 5. How We Will Work

We will follow a trunk-based development approach:

- Each task will be done on a separate branch  
- Work will be merged using pull requests  
- All work will be reviewed before merging  
- Feedback will be used to improve the content
